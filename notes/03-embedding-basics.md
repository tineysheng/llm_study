# 03 Embedding 基础：把文本变成语义向量

## 本课目标

上一课我们知道 RAG 要先从知识库里检索相关 chunk。但只靠关键词匹配会有明显问题：

- 用户问“怎么配置密钥”，文档写的是 `OPENAI_API_KEY`，关键词可能对不上
- 用户问“流式输出有什么用”，文档写的是 `Streaming`，关键词可能对不上
- 两句话意思相近，但用词不同，关键词检索可能找不到

Embedding 的作用就是把文本变成一组数字，让程序可以用数学方式比较“语义是否相近”。

```text
文本 -> Embedding 模型 -> 向量 -> 相似度计算 -> 找到最相关 chunk
```

## 本课必须先懂的术语

### 1. Embedding

Embedding 是把文本转换成向量的过程，也常用来指转换后的向量结果。

例如：

```text
"怎么设置 API Key" -> [0.12, 0.83, -0.21, ...]
"如何配置 OPENAI_API_KEY" -> [0.10, 0.80, -0.18, ...]
```

这两个句子用词不完全一样，但意思接近，所以它们的向量也应该接近。

面试表达：

> Embedding 是把文本映射到高维向量空间，让语义相近的文本在向量空间里距离更近，从而支持语义检索。

### 2. Vector（向量）

向量就是一组数字。

本课 demo 里为了好理解，手写了 3 维向量：

```go
[]float64{0.9, 0.1, 0.0}
```

真实 Embedding 模型通常会输出几百到几千维的向量。维度越高，不代表一定越好，但通常能表达更复杂的语义信息。

### 3. Dimension（维度）

维度就是向量里有多少个数字。

例如：

```text
[0.9, 0.1, 0.0] 是 3 维向量
[0.1, 0.2, 0.3, 0.4] 是 4 维向量
```

真实项目中，同一个向量库里的所有向量维度必须一致。否则无法计算相似度，也无法写入同一张向量索引。

### 4. Similarity（相似度）

相似度用来衡量两个向量有多接近。

在 RAG 里，常见做法是：

```text
用户问题向量 vs 每个 chunk 向量 -> 计算相似度 -> 排序 -> 取 Top-K
```

相似度越高，说明这个 chunk 越可能和用户问题相关。

### 5. Cosine Similarity（余弦相似度）

余弦相似度是 RAG 里常见的向量相似度计算方式。

它关注两个向量的方向是否接近，而不是长度是否接近。

结果通常可以这样理解：

| 余弦相似度 | 含义 |
|---|---|
| 接近 1 | 方向很接近，语义可能很相似 |
| 接近 0 | 关系弱或不相关 |
| 接近 -1 | 方向相反，语义可能相反 |

注意：真实 Embedding 检索里，分数高不等于答案一定正确，只代表“向量空间里更接近”。

## 为什么不用关键词匹配

关键词匹配只能看字面是否出现同一个词。

例如：

```text
问题：怎么配置密钥？
文档：运行前需要设置 OPENAI_API_KEY 环境变量。
```

关键词检索可能认为它们不相关，因为“密钥”和 `OPENAI_API_KEY` 字面不同。

Embedding 更关注语义：

```text
配置密钥 ≈ 设置 API Key ≈ 设置 OPENAI_API_KEY
```

这就是语义检索比关键词检索更适合 RAG 的原因。

## 本课代码

代码位置：

```text
02-rag\embedding-demo\main.go
```

运行方式：

```powershell
go run .\02-rag\embedding-demo
```

本课代码暂时不调用真实 Embedding API，而是手写几组向量，目的是先理解余弦相似度的计算逻辑：

1. 准备一个“用户问题向量”
2. 准备几条“文档向量”
3. 计算问题和每条文档的余弦相似度
4. 按相似度从高到低排序
5. 观察语义相关内容是否排在前面

下一课再调用真实 Embedding API，把自然语言文本转换成真正的模型向量。

## 如何看懂本课输出

你会看到类似结果：

```text
用户问题: 如何设置 OpenAI API Key？

相似度排序:
1. API Key 配置 similarity=0.994
2. JSON 结构化输出 similarity=0.226
3. Streaming 流式输出 similarity=0.159
```

这表示：

- `API Key 配置` 和问题最相关，所以排第 1
- `JSON 结构化输出`、`Streaming 流式输出` 和问题不太相关，所以分数低

真实 RAG 中，这一步会决定哪些 chunk 被塞进 Prompt。

## 本课常见误区

### 误区 1：Embedding 是关键词匹配

不是。Embedding 是语义向量，目标是让意思相近的文本在向量空间里更接近。

### 误区 2：相似度最高就一定是正确答案

不一定。相似度只是检索阶段的相关性信号。文档内容本身可能过时、错误，或者 chunk 切分不合理。

### 误区 3：Embedding 会让模型记住企业知识

不会。Embedding 只是把文本转成向量，方便检索。知识仍然存在外部知识库里。

### 误区 4：维度越高一定越好

不一定。维度影响表达能力、存储成本和检索成本。真实项目要看模型效果、成本、延迟和向量库支持情况。

## 当前重点

- Embedding 是文本到向量的转换
- 向量是一组数字，维度必须一致
- 余弦相似度衡量两个向量方向是否接近
- RAG 用相似度排序来选择 Top-K chunk
- Embedding 解决的是语义检索，不是让模型永久记住知识
